## 5.1 时间复杂度分析

### 5.1.1 为什么要分析算法效率？

假设你要在 100 万个电话号码中查找某个号码。一种方法是逐个比对——最坏情况下需要比对 100 万次。另一种方法是先把号码排序，然后每次折半查找——最坏情况下只需约 20 次比对。

两种方法的"快慢"差距，并不是靠买更快的计算机就能弥补的。100 万次和 20 次之间的差异，是算法本身的效率差异，是**算法复杂度**的差异。

算法复杂度分析不依赖于具体的计算机型号或编程语言，它描述的是**问题规模增长时，算法所需资源（时间、空间）的增长趋势**。这种抽象让我们能够在买计算机、写代码之前，就对算法的效率做出理论判断。

**小练习**：假设有一算法对 $n=100$ 运行 0.01 秒，$n=10000$ 运行 100 秒，估算其时间复杂度。

### 5.1.2 大 O 记法

**大 O 记法**（Big-O Notation）是描述算法复杂度的标准数学语言。它回答的问题是："当输入规模 $n$ 足够大时，算法的运行时间（或空间占用）的增长上界是什么？"

#### 形式定义

设 $f(n)$ 和 $g(n)$ 是定义在自然数上的两个函数。我们说 $f(n) = O(g(n))$，如果存在正常数 $c$ 和 $n_0$，使得对所有 $n \geq n_0$，有：

$$
0 \leq f(n) \leq c \cdot g(n)
$$

通俗地说：当 $n$ 足够大时，$f(n)$ 的增长速度不会超过 $g(n)$ 的某个常数倍。

**例 5.1**  设 $f(n) = 3n^2 + 2n + 1$，证明 $f(n) = O(n^2)$。

**证明**：当 $n \geq 1$ 时，

$$
3n^2 + 2n + 1 \leq 3n^2 + 2n^2 + n^2 = 6n^2
$$

取 $c = 6$，$n_0 = 1$，即满足大 O 定义。∎

这个例子说明了一个重要原则：**大 O 记法忽略低阶项和常数系数**。当 $n$ 很大时，$n^2$ 项支配了整个函数的增长，低阶项 $2n$ 和常数项 $1$ 可以忽略。

#### 大 O 记法的直觉理解

| 含义 | 大 O 表达 |
|------|-----------|
| 运行时间与输入规模无关 | $O(1)$ |
| 运行时间随 $\log n$ 增长 | $O(\log n)$ |
| 运行时间与 $n$ 成正比 | $O(n)$ |
| 运行时间与 $n \log n$ 成正比 | $O(n \log n)$ |
| 运行时间与 $n^2$ 成正比 | $O(n^2)$ |
| 运行时间随 $2^n$ 增长 | $O(2^n)$ |

#### 大 O 记法的严格相关记号

除了大 O（上界），还有几个相关记号：

- **$\Omega$（大 Omega）**：$f(n) = \Omega(g(n))$ 表示 $g(n)$ 是 $f(n)$ 的渐近下界。存在 $c, n_0 > 0$ 使得 $f(n) \geq c \cdot g(n)$ 对所有 $n \geq n_0$ 成立。
- **$\Theta$（大 Theta）**：$f(n) = \Theta(g(n))$ 表示 $f(n) = O(g(n))$ 且 $f(n) = \Omega(g(n))$，即 $f$ 和 $g$ 同阶。
- **$o$（小 o）**：$f(n) = o(g(n))$ 表示 $f(n) / g(n) \to 0$ 当 $n \to \infty$，即 $f$ 比 $g$ 增长慢得多。

**例 5.2**  下面的对比帮助理解：

| 函数关系 | 含义 |
|----------|------|
| $n^2 = O(n^3)$ | $n^2$ 不超过 $n^3$（真） |
| $n^3 \neq O(n^2)$ | $n^3$ 超过 $n^2$ 的任何常数倍 |
| $n^2 = \Omega(n)$ | $n^2$ 至少是 $n$ 的常数倍 |
| $n^2 = \Theta(2n^2 + n)$ | 两者同阶 |
| $n = o(n^2)$ | $n$ 比 $n^2$ 增长慢得多 |

**小练习**：判断并说明：$n^3 = O(n^2)$ 是否成立？

### 5.1.3 常见时间复杂度详解

#### $O(1)$ —— 常数时间

算法的执行时间与输入规模 $n$ **无关**。无论 $n=10$ 还是 $n=10^9$，执行步数固定。

**示例**：数组随机访问、哈希表查找（理想情况）、栈的压入/弹出。

```python
def get_first(arr):
    return arr[0]  # 无论数组多大，都是一步操作
```

**例 5.3**  以下代码也是 $O(1)$：

```python
def swap(arr, i, j):
    tmp = arr[i]
    arr[i] = arr[j]
    arr[j] = tmp
```

三条语句，每条执行一次。$O(1)$ 不要求一定是 1 步，只要是**常数步**即可。

#### $O(\log n)$ —— 对数时间

算法的执行时间与 $\log n$ 成正比。当 $n$ 翻倍时，时间仅增加一个**常数**（因为 $\log(2n) = \log n + 1$）。

**示例**：二分查找、平衡二叉搜索树的查找操作。

```python
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```

**为什么是 $\log_2 n$？** 每次迭代，搜索范围减半。从 $n$ 减到 1 需要 $\log_2 n$ 次迭代。在大 O 记法中，对数的底不重要——$\log_a n = \Theta(\log_b n)$，因为换底只差一个常数因子。

**例 5.4**  在 $10^6$ 个有序元素中二分查找，只需约 $\log_2 10^6 \approx 20$ 次比较。这比线性搜索快 50 000 倍。

#### $O(n)$ —— 线性时间

算法的执行时间与输入规模 $n$ 成正比。如果 $n$ 翻倍，时间也大约翻倍。

**示例**：数组遍历、线性搜索、计算总和。

```python
def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1
```

在无序数据中查找元素，线性搜索是唯一保证正确的方法。这正是 Grover 算法要解决的问题——它用量子计算的平方根加速将 $O(n)$ 降至 $O(\sqrt{n})$。

#### $O(n \log n)$ —— 线性对数时间

许多高效的排序算法运行在这个复杂度。

**示例**：归并排序、堆排序、快速排序（平均情况）。

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)
```

$O(n \log n)$ 是**比较排序**的下界——任何基于比较的排序算法在最坏情况下至少需要 $n \log n$ 次比较。这是信息论的一个基本结论：$n!$ 种排列需要 $\log(n!) \approx n \log n$ 比特信息来区分。

#### $O(n^2)$ —— 平方时间

算法的执行时间与 $n^2$ 成正比。$n$ 翻倍时，时间增长 4 倍。

**示例**：冒泡排序、选择排序、插入排序（最坏情况）、两两比较的嵌套循环。

```python
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        for j in range(n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
```

当 $n=10^4$ 时，$n^2 = 10^8$ 次操作，现代计算机还可以接受。当 $n=10^6$ 时，$10^{12}$ 次操作就不可行了。

#### $O(2^n)$ —— 指数时间

算法的执行时间随 $n$ 指数增长。$n$ 每增加 1，时间翻倍（或翻更多倍）。

**示例**：暴力搜索所有子集、旅行商问题的穷举解法、递归计算斐波那契数列（不加记忆化）。

```python
def fibonacci_recursive(n):
    if n <= 1:
        return n
    return fibonacci_recursive(n - 1) + fibonacci_recursive(n - 2)
```

这个递归展开的调用树是一棵满二叉树，节点数约 $2^n$。当 $n=100$ 时，$2^{100} \approx 10^{30}$ 步，即使每步只需 $10^{-9}$ 秒，也需要 $10^{21}$ 秒——远超宇宙年龄（$4.3 \times 10^{17}$ 秒）。

指数时间算法在实际中只适用于非常小的 $n$。量子计算中的某些指数加速（如 Shor 算法将因数分解的指数时间降为多项式时间）因此具有革命性意义。

**小练习**：比较 $O(\log n)$ 和 $O(\sqrt{n})$ 的增长速度，哪个更快？

### 5.1.4 不同复杂度的直观对比

下表展示了当 $n$ 增大时，各复杂度函数的实际增长：

| $n$ | $O(1)$ | $O(\log n)$ | $O(n)$ | $O(n \log n)$ | $O(n^2)$ | $O(2^n)$ |
|-----|--------|-------------|--------|----------------|-----------|-----------|
| 10 | 1 | ~3 | 10 | ~33 | 100 | 1,024 |
| 100 | 1 | ~7 | 100 | ~664 | 10,000 | $10^{30}$ |
| 1,000 | 1 | ~10 | 1,000 | ~9,966 | $10^6$ | 天文数字 |
| $10^6$ | 1 | ~20 | $10^6$ | ~$2\times 10^7$ | $10^{12}$ | 不可行 |
| $10^9$ | 1 | ~30 | $10^9$ | ~$3\times 10^{10}$ | $10^{18}$ | 不可行 |

这张表传达了一个核心信息：**复杂度决定了算法能解决多大规模的问题**。一个好的算法可以让原本不可解的问题变得可解，而不只是让可解问题变得更快。

**小练习**：对于 $n=10^6$，$O(n)$ 和 $O(n\log n)$ 算法的时间差距约为多少倍？

### 5.1.5 空间复杂度

**空间复杂度**（Space Complexity）衡量算法运行所需的存储空间随输入规模 $n$ 的增长趋势，同样用大 O 记法描述。

**例 5.5**  就地排序算法（如冒泡排序）使用原数组排序，只需额外 $O(1)$ 的空间。而归并排序需要 $O(n)$ 的额外空间来存储临时数组。

```python
# 空间复杂度 O(1)
def sum_array(arr):
    total = 0          # 只有一个变量
    for x in arr:
        total += x
    return total

# 空间复杂度 O(n)
def duplicate_array(arr):
    return [x for x in arr]   # 创建了一个新数组
```

**时间-空间权衡**：许多算法可以在"用时间换空间"或"用空间换时间"之间做选择。动态规划的核心思想就是用额外空间（存储子问题的解）来换取指数级的时间节省。

> **量子计算的视角**：量子算法的时间复杂度往往与量子比特数（空间）紧密相关。Grover 算法用 $O(\sqrt{n})$ 次查询代替 $O(n)$ 次，但需要 $O(\log n)$ 个量子比特的额外空间来构建叠加态。理解经典复杂度分析，是理解量子加速的起点。

**小练习**：描述一个空间复杂度 $O(1)$ 但时间复杂度 $O(n^2)$ 的算法。

## 5.2 P 与 NP

### 5.2.1 问题的分类

在计算复杂性理论中，我们按"解决问题所需的时间"对问题分类。最重要的两个类是 P 和 NP。

#### P 类：多项式时间可解

**P**（Polynomial time）类包含所有可以在**多项式时间**内解决的问题。如果一个问题存在算法，其时间复杂度为 $O(n^k)$（其中 $k$ 是常数），则该问题属于 P。

P 类中的问题被认为是"高效可解的"或"易处理的"（tractable）。$O(n)$、$O(n^2)$、$O(n^{100})$ 都是多项式，但实践中 $k$ 不会太大。

**属于 P 的问题示例**：
- 排序（$O(n \log n)$）
- 线性搜索（$O(n)$）
- 矩阵乘法（$O(n^{2.81})$，Strassen 算法）
- 判断一个数是否为质数（AKS 算法，$O(\log^{6} n)$）
- 求最短路径（Dijkstra 算法，$O(n^2)$）
- 连通性判断（$O(n)$）

**例 5.6**  "给定一个图，判断从点 A 到点 B 是否存在路径"属于 P。使用广度优先搜索，时间复杂度 $O(n + m)$，其中 $n$ 是顶点数，$m$ 是边数。

#### NP 类：多项式时间可验证

**NP**（Nondeterministic Polynomial time）类包含所有可以在多项式时间内**验证**解的问题。更准确地说："如果一个问题的一个候选解能在多项式时间内被验证是否正确"，那么这个问题属于 NP。

注意：**NP 不是"非多项式"**，而是"非确定性多项式"。

**属于 NP 的问题示例**：
- 因数分解：给定 $n$ 和一个候选因子 $d$，可以在 $O(1)$ 时间内验证 $d$ 是否整除 $n$。
- 哈密顿回路：给定一个图和一个顶点序列，可以在 $O(n)$ 时间内验证该序列是否构成哈密顿回路。
- 子集和：给定一组数和一个候选子集，可以在 $O(n)$ 时间内验证该子集的和是否等于目标值。
- SAT（布尔可满足性）：给定一个布尔公式和一组变量赋值，可以在 $O(n)$ 时间内验证公式是否为真。

**例 5.7**  **Satisfiability（SAT）问题** 是 NP 的典型代表。问题是：给定一个由 AND、OR、NOT 组成的布尔公式，是否存在一组变量赋值使公式为真？检查一个候选赋值只需要代入计算（多项式时间），但找到这组赋值可能需要指数时间搜索。

#### P 与 NP 的关系

显然，$P \subseteq NP$：如果一个问题的解能在多项式时间内找到，自然也能在多项式时间内验证。

**但 $P = NP$ 吗？** 这是计算机科学中最重要的未解问题，也是 Clay 数学研究所的千禧年大奖难题之一（奖金 100 万美元）。

直观上，P 是"易于求解"，NP 是"易于验证"。许多问题求解困难但验证容易。如果 $P = NP$，那么所有易于验证的问题都易于求解——这将对密码学、人工智能、科学计算产生颠覆性影响。绝大多数研究者相信 $P \neq NP$。

> **量子计算的关联**：量子计算并不直接回答 $P = NP$ 问题。量子计算机能多项式时间解决的问题构成 BQP 类（Bounded-error Quantum Polynomial time）。一般认为 $P \subseteq BQP$，但 $BQP$ 与 $NP$ 的关系尚不明确。Shor 算法表明因数分解属于 BQP，而因数分解被认为是 NP 中但不在 P 中的（虽然因数分解未被证明是 NP 完全的）。这是量子计算之所以重要的重要原因。

### 5.2.2 NP 完全与 NP 困难

#### NP 完全问题

**NP 完全**（NP-Complete，简称 NPC）是 NP 类中最"难"的问题的子集。一个问题如果满足两个条件，它就是 NP 完全的：

1. 该问题属于 NP（解可快速验证）。
2. 该问题是**NP 困难的**：NP 中的任何问题都可以在多项式时间内归约到该问题。

**归约**（Reduction）的概念至关重要。如果问题 A 能在多项式时间内转换为问题 B，并且 B 的解能直接给出 A 的解，我们就说 A 可以**多项式归约**到 B。记作 $A \leq_p B$。

归约意味着 B 至少和 A 一样难。如果 A 是 NP 完全的，B 也在 NP 中，那么 B 也是 NP 完全的。

**NP 完全问题的意义**：如果任何一个 NP 完全问题存在多项式时间算法，那么所有 NP 问题都存在多项式时间算法（即 $P = NP$）。反之，如果某个 NP 完全问题被证明没有多项式时间算法，那么所有 NP 完全问题都没有多项式时间算法。

**第一个 NP 完全问题**：Cook-Levin 定理（1971 年）证明了 **SAT 问题**是 NP 完全的。这是计算复杂性理论的里程碑。

**其他著名的 NP 完全问题**：
- 旅行商问题（判定版本：是否存在长度 ≤ L 的回路）
- 图着色问题（判断是否可以用 k 种颜色给图着色，使相邻顶点颜色不同）
- 背包问题（判定版本）
- 顶点覆盖问题
- 哈密顿回路问题

#### NP 困难问题

**NP 困难**（NP-Hard）问题的定义比 NP 完全更宽松：一个问题 X 是 NP 困难的，如果所有 NP 问题都能多项式归约到 X。但 X **不一定属于 NP**（即其解不一定能在多项式时间内验证）。

NP 困难问题至少和任何 NP 问题一样难，甚至可能更难。例如：
- **停机问题**（Halting Problem）是 NP 困难的，但它甚至不是可判定的。
- **最优旅行商问题**（求最短回路，而非判断是否存在某长度的回路）是 NP 困难的，但不一定是 NP 完全的（因为最优解可能不易验证）。

```
图示：P ⊆ NP ⊆ NP-完全 ⊆ NP-困难。注意 NP-困难包含 NP-完全，且包含不可判定的问题。

     NP-困难
     ┌──────────────────┐
     │  NP-完全          │
     │  ┌──────┐         │
     │  │  NP  │         │
     │  │ ┌──┐ │         │
     │  │ │P │ │         │
     │  │ └──┘ │         │
     │  └──────┘         │
     │  (停机问题等)      │
     └──────────────────┘
```

### 5.2.3 因数分解不是 NP 完全的

这是本章最重要的结论之一，因为它直接关系到 Shor 算法的意义。

**整数因数分解**（Integer Factorization）：给定合数 $N$，找到它的非平凡因子（1 和自身之外的因子）。

这个问题的状态是：
- 因数分解**属于 NP**：给定一个因子 $d$，验证 $d$ 整除 $N$ 可以在 $O(1)$ 时间内完成。
- 因数分解**不被认为属于 P**：最著名的经典算法（数域筛法）的时间复杂度为 $O\big(e^{(c+o(1))(\log N)^{1/3}(\log\log N)^{2/3}}\big)$，是指数级（严格说是亚指数级）。
- 因数分解**不是 NP 完全的**（除非 $P = NP$）。

为什么因数分解不是 NP 完全的？因为没有人能证明 NP 中的每个问题都可以多项式归约到因数分解。实际上，因数分解的"难度"有着特殊的结构：它介于 P 和 NP 完全之间。人们倾向于认为它既不在 P 中，也不是 NP 完全的。

> **直觉解释**：NP 完全问题（如 SAT）在结构上具有一种"通用性"——任何 NP 问题都可以编码为 SAT。但因数分解似乎没有这种通用性。你可以把 SAT 问题编码为因数分解问题吗？没有人知道怎么做。因数分解的特殊结构使它处于一个独特的生态位。

**为什么这对量子计算至关重要？**

RSA 密码体制的安全性基于"因数分解对经典计算机是困难的"这一假设。如果因数分解是 NP 完全的，那么破解 RSA 就至少和解决任何 NP 问题一样困难。但因数分解不是 NP 完全的，这意味着它的难度可能低于某些 NP 完全问题。

Shor 算法在量子计算机上可以在 $O((\log N)^3)$ 时间内分解整数——这是多项式时间。这意味着**量子计算对 RSA 构成了实质性威胁**，因为 RSA 的安全性只依赖于因数分解的经典难度，而非 NP 完全性。

### 5.2.4 离散对数问题

**离散对数问题**（Discrete Logarithm Problem，DLP）与因数分解密切相关，是另一个对密码学至关重要的问题。

**定义 2.1**：设 $p$ 为质数，$g$ 为模 $p$ 的生成元（原根）。给定 $y = g^x \bmod p$，求 $x$（记为 $x = \log_g y$）。

- **正向计算（幂运算）**：给定 $g$、$p$ 和 $x$，计算 $y = g^x \bmod p$ 可以在 $O(\log x)$ 时间内用快速幂完成。这是**容易的**。
- **逆向计算（离散对数）**：给定 $g$、$p$ 和 $y$，求 $x$ 目前没有已知的多项式时间经典算法。

**离散对数问题的状态**：
- 属于 NP（验证简单：计算 $g^x \bmod p$ 看看是否等于 $y$）。
- 不被认为属于 P。
- 不被认为是 NP 完全的（与因数分解类似）。
- Shor 算法同样可以多项式时间求解离散对数问题。

**离散对数的密码学应用**：
- Diffie-Hellman 密钥交换
- ElGamal 加密体制
- 数字签名算法（DSA）

> **量子计算的关联**：Shor 算法能够高效求解离散对数问题（和因数分解一样）。这意味着几乎所有基于离散对数的经典密码体制都被量子计算威胁。

## 5.3 经典算法示例

### 5.3.1 搜索算法

搜索是最基本的计算任务之一。我们比较两种经典方法。

#### 线性搜索

**思想**：从第一个元素开始，依次检查每个元素，直到找到目标。

```python
def linear_search(arr, target):
    for i in range(len(arr)):
        if arr[i] == target:
            return i
    return -1
```

- **时间复杂度**：$O(n)$（最坏情况需要检查所有元素）
- **空间复杂度**：$O(1)$
- **适用场景**：数据无序、数据量小

线性搜索是"盲目"搜索的代表——它没有利用数据的任何结构信息。

#### 二分搜索

**思想**：利用数据的有序性，每步将搜索范围缩小一半。

```python
def binary_search(arr, target):
    left, right = 0, len(arr) - 1
    while left <= right:
        mid = (left + right) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```

- **时间复杂度**：$O(\log n)$
- **空间复杂度**：$O(1)$（迭代版）
- **前提**：数据必须有序

**对比**：

| 算法 | 时间复杂度 | 空间复杂度 | 数据要求 |
|------|-----------|-----------|---------|
| 线性搜索 | $O(n)$ | $O(1)$ | 无 |
| 二分搜索 | $O(\log n)$ | $O(1)$ | 有序 |

对于 $n = 10^6$，线性搜索最坏需 $10^6$ 步，二分搜索只需约 20 步。

> **量子视角**：Grover 搜索算法可以在 $O(\sqrt{n})$ 时间内完成无序搜索。这与经典线性搜索 $O(n)$ 相比是平方加速。对于 $n=10^6$，Grover 算法约需 1000 步——比二分搜索慢，但二分搜索要求数据有序，而 Grover 算法不需要。

### 5.3.2 排序算法复杂度

排序是最经典的算法问题之一。下表总结主要排序算法的复杂度：

| 算法 | 最好情况 | 平均情况 | 最坏情况 | 空间复杂度 | 稳定性 |
|------|---------|---------|---------|-----------|--------|
| 冒泡排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 |
| 选择排序 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 不稳定 |
| 插入排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 |
| 归并排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | 稳定 |
| 快速排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n^2)$ | $O(\log n)$ | 不稳定 |
| 堆排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ | 不稳定 |

**排序下界定理**：任何基于比较的排序算法最坏情况下的时间复杂度下界为 $\Omega(n \log n)$。证明思路：$n$ 个元素有 $n!$ 种排列，每次比较最多排除一半排列，因此至少需要 $\log_2(n!)$ 次比较。由 Stirling 公式，$\log(n!) \approx n\log n$。

> **量子排序**：量子计算中的排序算法可以达到 $O(\sqrt{n} \log n)$ 的查询复杂度（基于 Grover 搜索的变体），但在实际意义上有局限。

### 5.3.3 动态规划

**动态规划**（Dynamic Programming，DP）是一种通过将原问题分解为重叠子问题，并存储子问题的解来避免重复计算的方法。

**核心思想**：记住已经算过的结果。

#### 经典例子：斐波那契数列

**朴素递归**（指数时间）：
```python
def fib_rec(n):
    if n <= 1:
        return n
    return fib_rec(n-1) + fib_rec(n-2)
```
复杂度 $O(2^n)$——重复计算太多。

**动态规划（自底向上）**：
```python
def fib_dp(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]
```
复杂度 $O(n)$，空间 $O(n)$。

**进一步优化**：只用两个变量，空间 $O(1)$：
```python
def fib_opt(n):
    if n <= 1:
        return n
    a, b = 0, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b
```

#### 经典 DP 问题示例

**0/1 背包问题**：给定 $n$ 个物品，每个物品有重量 $w_i$ 和价值 $v_i$，背包容量为 $W$，求最大价值。

设 $dp[i][w]$ 表示从前 $i$ 个物品中选择，总重量不超过 $w$ 的最大价值。递推关系：

$$
dp[i][w] = \max(dp[i-1][w], dp[i-1][w-w_i] + v_i) \quad (\text{如果 } w_i \leq w)
$$

时间复杂度 $O(nW)$，空间 $O(nW)$（可优化为 $O(W)$）。

**最长公共子序列（LCS）**：给定两个字符串，求它们的最长公共子序列长度。

$$
dp[i][j] = \begin{cases}
dp[i-1][j-1] + 1, & \text{如果 } s_1[i] = s_2[j] \\
\max(dp[i-1][j], dp[i][j-1]), & \text{其他}
\end{cases}
$$

时间复杂度 $O(nm)$。

> **量子关联**：动态规划的"记住中间结果"思想与量子计算中的"量子并行性"有某种精神上的共鸣。动态规划用空间换时间，量子计算用叠加态换并行性。但两者的本质完全不同。

### 5.3.4 随机化算法

**随机化算法**（Randomized Algorithm）在运行过程中使用随机数做出决策。有时候，"抛硬币"比"仔细分析"更高效。

#### 类型一：Las Vegas 算法

**特点**：总是返回正确结果，但运行时间可能不同。

**示例**：随机化快速排序——随机选择枢轴（pivot），避免最坏情况。

```python
import random

def quicksort_random(arr):
    if len(arr) <= 1:
        return arr
    pivot = random.choice(arr)  # 随机选枢轴
    left = [x for x in arr if x < pivot]
    mid  = [x for x in arr if x == pivot]
    right= [x for x in arr if x > pivot]
    return quicksort_random(left) + mid + quicksort_random(right)
```

随机化快速排序的期望时间复杂度为 $O(n\log n)$，最坏情况概率极低。

#### 类型二：Monte Carlo 算法

**特点**：运行时间固定，但结果可能有（可控制的）错误概率。

**示例**：素性测试（Miller-Rabin 算法）。

```python
def is_probable_prime(n, k=10):
    """Monte Carlo 素性测试，错误概率 < 4^{-k}"""
    if n < 2:
        return False
    # ... Miller-Rabin 测试细节
    # 如果返回 "合数"，则一定是合数
    # 如果返回 "质数"，则以高概率正确
    return probably_prime
```

有些问题是"单侧错误"的：如果算法回答"是"，答案几乎一定是正确的；如果回答"否"，可能是错的。通过多次运行，可以任意降低错误概率。

**为什么随机化算法重要？**
1. **效率**：许多随机化算法比已知的确定性算法更快。
2. **简洁性**：代码通常更简单。
3. **量子关联**：量子算法本质上是概率性的——它们以高概率返回正确答案。量子算法的"测量"步骤就相当于一个随机化过程。

> **量子视角**：量子计算可以看作随机化计算的推广。经典随机化算法用概率分布处理不确定性，量子算法用概率幅（复数）处理量子不确定性。量子算法的输出也是概率性的（例如 Grover 算法以高概率返回正确目标）。

### 5.3.5 近似算法

对于 NP 完全问题，如果找不到精确解，可以退而求其次：在多项式时间内找到一个"足够好"的解。

**近似算法**（Approximation Algorithm）在多项式时间内返回一个解，其质量与最优解之比有界。

**示例**：旅行商问题的近似算法。

对于满足 **三角不等式**的旅行商问题（即 $dist(A,C) \leq dist(A,B) + dist(B,C)$），存在一个 $2$-近似算法（即返回的路径长度不超过最优解的两倍）：

1. 生成最小生成树（MST）。
2. 沿 MST 进行深度优先遍历，跳过已经访问过的城市（捷径）。

这个算法的时间复杂度为 $O(n^2)$（生成 MST 的复杂度）。

**近似比**：如果算法返回的解的目标函数值不超过最优解的 $\alpha$ 倍，则称该算法为 $\alpha$-近似算法。

| 问题 | 近似比 | 算法 |
|------|--------|------|
| 顶点覆盖 | 2 | 贪心匹配算法 |
| 旅行商（三角不等式） | 2 | MST 遍历 |
| 集合覆盖 | $\ln n$ | 贪心算法 |
| 背包问题 | $(1+\varepsilon)$ | 动态规划（FPTAS） |

> **量子关联**：目前已知的量子近似算法在近似比上对经典算法没有根本性的优势。Grover 搜索可以用来加速某些近似算法中的子程序（如搜索最优参数），但近似算法本身的理论界限在经典和量子设定下基本相同。

## 5.4 密码学基础

### 5.4.1 密码学简介

密码学（Cryptography）研究如何在敌人存在的环境中安全通信。经典的密码系统（如 Caesar 密码、Enigma 机）被现代计算机轻松破解。现代密码学建立在**计算复杂性理论**的基础上：一个密码系统是安全的，不是因为"绝对无法破解"，而是因为"破解的计算代价太大"。

这种安全性的核心假设是某些计算问题是**困难的**。量子计算威胁的恰恰是这些假设。

### 5.4.2 RSA 密码体制

RSA（Rivest-Shamir-Adleman，1977 年）是使用最广泛的公钥密码体制之一。它的安全性基于**大整数因数分解的困难性**。

#### 密钥生成

1. 随机选择两个大质数 $p$ 和 $q$（通常各 1024 比特以上）。
2. 计算 $n = p \times q$。
3. 计算欧拉函数 $\phi(n) = (p-1)(q-1)$。
4. 选择公钥指数 $e$，满足 $1 < e < \phi(n)$ 且 $\gcd(e, \phi(n)) = 1$（通常取 $e = 65537$）。
5. 计算私钥 $d$，满足 $e \times d \equiv 1 \pmod{\phi(n)}$（即 $d$ 是 $e$ 模 $\phi(n)$ 的逆元）。

**公钥**：$(n, e)$；**私钥**：$(d, p, q)$。

#### 加密

将消息 $m$ 表示为整数 $0 \leq m < n$，加密为密文 $c$：

$$
c = m^e \bmod n
$$

#### 解密

$$
m = c^d \bmod n
$$

RSA 的正确性由欧拉定理保证：$m^{\phi(n)} \equiv 1 \pmod{n}$，所以 $m^{ed} \equiv m^{1 + k\phi(n)} \equiv m \pmod{n}$。

#### RSA 的安全性

要破解 RSA，攻击者需要从公钥 $(n, e)$ 中恢复私钥 $d$。最直接的方法是分解 $n$ 得到 $p$ 和 $q$。一旦 $p$ 和 $q$ 已知，就可以计算 $\phi(n) = (p-1)(q-1)$，进而计算 $d$。

因此，**RSA 的安全性等价于大整数因数分解的困难性**（严格说还有语义安全性，但核心在因数分解）。

**例 5.8**  一个过于简单的示例（仅为演示）：
- $p = 61$，$q = 53$
- $n = 61 \times 53 = 3233$
- $\phi(n) = 60 \times 52 = 3120$
- $e = 17$（公钥指数）
- $d = 2753$（因为 $17 \times 2753 = 46801 = 15 \times 3120 + 1$）
- 加密消息 $m = 65$：$c = 65^{17} \bmod 3233 = 2790$
- 解密：$2790^{2753} \bmod 3233 = 65$

### 5.4.3 因数分解的经典难度

目前已知最快的经典因数分解算法是**数域筛法**（Number Field Sieve, NFS）。其时间复杂度约为：

$$
O\left(e^{(c + o(1))(\log N)^{1/3}(\log\log N)^{2/3}}\right)
$$

其中 $c \approx 1.9$。

这个复杂度被称为 **亚指数时间**——介于多项式时间和指数时间之间。

下表展示了因数分解所需的大致工作量：

| $n$ 的比特数 | 十进制位数 | 经典难度 | 分解时间估计（2020 年代技术） |
|-------------|-----------|---------|---------------------------|
| 512 比特 | ~154 位 | 已经不安全 | 数分钟~数小时 |
| 1024 比特 | ~308 位 | 接近不可行 | 数万核心年 |
| 2048 比特 | ~617 位 | 当前安全 | 无法估计（远大于宇宙年龄） |
| 4096 比特 | ~1233 位 | 非常安全 | 无法估计 |

**重要结论**：随着 $n$ 的比特数线性增长，因数分解的难度呈超多项式（亚指数/指数）级增长。这就是为什么 RSA 的安全依赖于足够大的密钥长度。

### 5.4.4 离散对数问题

如 5.2.4 节所述，离散对数问题（DLP）是另一个经典困难问题。在密码学中，它通常以两种形式出现：

**1. 模质数群的离散对数**：
- 给定质数 $p$，生成元 $g$，以及 $y = g^x \bmod p$，求 $x$。
- 用于 Diffie-Hellman 密钥交换、ElGamal 加密、DSA 签名。

**2. 椭圆曲线离散对数**（更高效）：
- 给定椭圆曲线上的点 $G$ 和 $Y = xG$，求 $x$。
- 称为 **椭圆曲线密码**（Elliptic Curve Cryptography, ECC）。
- 与 RSA 相比，ECC 用更短的密钥提供同等安全性（256 比特 ECC ≈ 3072 比特 RSA）。

**例 5.9**   Diffie-Hellman 密钥交换过程：

1. Alice 和 Bob 公开约定质数 $p$ 和生成元 $g$。
2. Alice 选随机数 $a$，计算 $A = g^a \bmod p$ 发送给 Bob。
3. Bob 选随机数 $b$，计算 $B = g^b \bmod p$ 发送给 Alice。
4. Alice 计算 $K = B^a \bmod p = g^{ba} \bmod p$。
5. Bob 计算 $K = A^b \bmod p = g^{ab} \bmod p$。
6. 两人得到相同的共享密钥 $K$。

窃听者看到 $p$、$g$、$A$、$B$，但无法从 $A = g^a$ 计算出 $a$（离散对数困难），也无法从 $B = g^b$ 计算出 $b$，因此无法得到 $K$。

### 5.4.5 为什么量子计算威胁 RSA

#### Shor 算法的核心洞察

1994 年，Peter Shor 提出了可以在量子计算机上多项式时间内分解整数和求解离散对数的算法。这就是著名的 **Shor 算法**。

Shor 算法将因数分解转化为**寻找函数周期**的问题：

1. 随机选择 $a < N$，计算 $\gcd(a, N)$。如果 $\gcd(a, N) \neq 1$，则找到了因子，结束。
2. 否则，考虑函数 $f(x) = a^x \bmod N$。这个函数是周期性的。设其最小正周期为 $r$（即 $a^r \equiv 1 \pmod N$）。
3. 如果 $r$ 是偶数，计算 $a^{r/2} \pm 1$。如果 $a^{r/2} \not\equiv \pm 1 \pmod N$，则 $\gcd(a^{r/2} - 1, N)$ 是 $N$ 的非平凡因子。
4. 如果上述条件不满足，换一个 $a$ 重试。

关键步骤是"找到函数 $f(x) = a^x \bmod N$ 的周期 $r$"。经典计算机上找周期需要指数时间——但量子计算机可以用**量子傅里叶变换**（Quantum Fourier Transform）在 $O((\log N)^3)$ 时间内完成。

**为什么经典计算机找周期困难？** 因为函数 $f(x)$ 是看似"随机"的，经典计算机需要逐个计算并比较大量的 $x$ 值才能找到周期。量子计算机利用叠加态可以同时"计算"所有 $x$ 对应的 $f(x)$，并通过量子傅里叶变换提取出周期信息。

#### Shor 算法的复杂度

| 步骤 | 经典复杂度 | 量子复杂度（Shor） |
|------|-----------|------------------|
| 因数分解 | $O(e^{c(\log N)^{1/3}(\log\log N)^{2/3}})$ | $O((\log N)^3)$ |
| 离散对数 | 类似 | $O((\log N)^3)$ |

#### 对 RSA 的具体威胁

- 2048 比特 RSA 的因数分解在经典计算机上需要**天文时间**。
- 有了一台足够大的容错量子计算机，Shor 算法可以在**数小时甚至数分钟**内分解同样的密钥。

所以说，**量子计算不是"更快"的经典计算**——它从根本上改变了某些问题的难度分类。因数分解从"经典困难"变成了"量子容易"。

> **但请注意**：目前（2020 年代）还没有足够大的容错量子计算机来分解 2048 比特 RSA。Shor 算法需要数千个逻辑量子比特，而每个逻辑量子比特又需要数千个物理量子比特来纠错。当前量子计算机的规模大约在几十到数百物理量子比特的级别。不过，密码学界已经在积极部署"后量子密码"（Post-Quantum Cryptography）标准，以应对未来量子计算对 RSA 和 ECC 的威胁。

## 5.5 不可计算性

### 5.5.1 停机问题

你可能以为"只要给足够多的时间，任何问题都能用计算机解决"。但事实并非如此。有些问题在数学上就是**不可计算**（undecidable）的——没有任何算法能在有限步内解决它们。

最著名的不可计算问题是**停机问题**（Halting Problem）。

#### 问题描述

> 给定一个程序 $P$ 和它的输入 $I$，判断 $P$ 在输入 $I$ 上是否会最终终止（停机），还是会永远运行下去。

这个问题看起来很简单？能不能写一个"停机检测器"程序，输入任意程序和输入，输出"停机"或"不停机"？

艾伦·图灵在 1936 年证明了：**停机问题是不可判定的**。不存在一个通用算法能对任意程序和输入判断是否停机。

#### 证明思路（反证法）

假设存在一个"停机检测器"函数 `halts(P, I)`，它：
- 如果程序 $P$ 在输入 $I$ 上停机，返回 `True`。
- 如果程序 $P$ 在输入 $I$ 上永不停机，返回 `False`。

现在，用这个函数构造一个新程序 `contradiction(P)`：

```python
def contradiction(P):
    if halts(P, P):          # 如果 P 在自己的输入上停机
        while True:          # 进入无限循环
            pass
    else:                    # 如果 P 在自己的输入上不停机
        return               # 立即返回（停机）
```

现在问：`contradiction(contradiction)` 是否停机？

- 如果 `halts(contradiction, contradiction)` 返回 `True`（说我停机），那么 `contradiction(contradiction)` 会进入无限循环——**不停机**。矛盾！
- 如果 `halts(contradiction, contradiction)` 返回 `False`（说我不停机），那么 `contradiction(contradiction)` 会立即返回——**停机**。矛盾！

无论哪种情况，`halts` 的判断都是错的。因此，`halts` 不可能存在。停机问题是不可判定的。

#### 这个证明为什么重要？

1. **计算的根本局限**：即使拥有无限的资源和时间，有些问题就是无法用算法解决。
2. **对量子计算同样适用**：停机问题的不可判定性同样适用于量子计算机。量子计算不能解决经典不可计算的问题。
3. **方法论意义**：它告诉我们，有些"不存在性"结果是可以通过数学严格证明的——不是"还没找到算法"，而是"不可能有算法"。

#### 停机问题在实际中的含义

虽然停机问题是不可判定的，但这并不意味着我们永远无法确定任何程序是否停机。对于许多具体的程序，我们可以通过分析（或直接运行）来判断它们是否停机。图灵证明的是：**没有一个通用的、能对所有程序都正确判断的算法**。

实际中的编译器静态分析、代码优化器、程序验证工具都在"尝试"判断某些程序属性，它们在某些情况下有效，但不可能对所有情况都完美。

### 5.5.2 其他不可计算问题

一旦理解了停机问题是不可判定的，就可以用**归约**的方法证明更多问题不可判定。如果问题 A 能归约到问题 B，那么 B 至少和 A 一样难。如果把停机问题归约到问题 X，那么 X 也是不可判定的（或者至少是 NP-困难的）。

以下是几个著名的不可判定问题：

**1. 程序等价性问题**
- 问题：给定两个程序 $P_1$ 和 $P_2$，它们是否对**所有输入**产生相同的输出？
- 不可判定性证明：如果程序等价性是可判定的，就可以用它来判断停机问题。

**2. Hilbert 第十问题（整数解判定）**
- 问题：给定一个整数系数的多项式方程，判断它是否有整数解。
- 希尔伯特在 1900 年提出了这个问题。1970 年，Matiyasevich 证明了它是不可判定的。
- 例：$x^2 - 5y^2 + z = 0$ 是否有整数解？没有通用算法能回答所有这类问题。

**3. 字问题（半群）**
- 问题：给定一组生成元和关系，判断两个不同的表示是否等价。
- 不可判定。

**4. Post 对应问题**
- 问题：给定一组骨牌（每个骨牌上有上下两串符号），能否排成一行使上下串相同？
- 不可判定，虽然问题描述极其简单。

**5. 优化问题的一些非近似性**
- 某些 NP 完全问题的近似版本也是不可判定的（即无法在给定近似比内求解）。

### 5.5.3 复杂度类之间的关系图

为了帮助理解，下面给出更完整的复杂度类关系图（公认观点，$P \neq NP$ 假设）：

```
                    ALL（所有问题）
                   /       \
             可判定的     不可判定的（停机问题等）
              /    \
        可计算的   不可计算的
         /    \
       PSPACE（多项式空间）
      /    \
    NP     co-NP（补NP）
   / \     /
  P   NP完全
 / \     /
LOGSPACE 等

       BQP（量子多项式时间）
       /  \
      P   （某些在NP但不在P中的问题）
```

**重要说明**：
- $P \subseteq NP \subseteq PSPACE \subseteq EXPTIME$（指数时间）
- $P \neq EXPTIME$（已知结论——存在必定需要指数时间的问题）
- $P$ 与 $NP$ 的关系未知（千禧年难题）
- $NP$ 与 $BQP$ 的关系未知
- 不可判定问题（如停机问题）不在任何复杂度类中——它们根本没有算法解

#### 总结：量子计算能做什么，不能做什么

| 能做什么 | 不能做什么 |
|---------|-----------|
| 多项式时间分解整数（Shor 算法） | 解决停机问题（不可判定） |
| 平方加速无序搜索（Grover 算法） | 解决 NP 完全问题（尚不明确） |
| 模拟量子物理系统（Feynman 的初衷） | 超越计算复杂性的根本界限 |
| 某些密码学问题的多项式时间求解 | 使 $P = NP$（不直接相关） |

量子计算不是"万能加速器"。它只在特定问题上提供加速，并且不能打破不可判定性的壁垒。理解经典算法与复杂度的这些基础，才能真正理解量子算法的力量和局限。

> **本章总结**
>
> 1. **算法复杂度**用大 O 记法描述输入规模增长时资源消耗的增长趋势。$O(1)$、$O(\log n)$、$O(n)$、$O(n\log n)$、$O(n^2)$、$O(2^n)$ 分别代表不同增长等级。
>
> 2. **P 和 NP** 是计算复杂性理论的核心。P 是多项式时间可解的问题集合；NP 是多项式时间可验证的问题集合。$P \neq NP$ 是尚未解决的千禧年难题。
>
> 3. **因数分解**不是 NP 完全的——这意味着它的难度介于 P 和 NP 完全之间。Shor 算法在量子计算机上可以多项式时间分解整数，这是量子计算威胁 RSA 密码体制的根本原因。
>
> 4. **RSA 密码体制**的安全性基于大整数因数分解的困难性。离散对数问题（Diffie-Hellman 和 ECC 的基础）同样被 Shor 算法威胁。
>
> 5. **不可计算性**是计算的最终边界。停机问题的不可判定性证明了存在任何计算机（包括量子计算机）都无法解决的问题。
>
> 6. **量子计算不万能**——它不能解决 NP 完全问题（尚不明确），不能解决不可判定问题。它的加速仅限于具有特定数学结构的问题（如周期发现、无序搜索）。
>
> 掌握这些经典计算的理论基础，是进入量子算法世界的必要准备。下一章将介绍信息论，它是量子信息理论的经典前奏。
